# Jobs To Be Done

## Job

When I have a small web-product idea and powerful AI coding tools available, I want to turn the idea into a validated, explainable product decision process before implementation momentum locks me into the wrong solution, so that I can build only what is worth testing and later reconstruct why the product took its current form.

## Context / situation

The user is comfortable working in a code repository and Cursor. Ideas may begin as a few sentences, while implementation can become large quickly. The user may work locally or with Cloud Agents, may ask multiple AI agents for independent views, and may return to the project after prior chat context is no longer convenient or complete.

## Desired outcome

- The current product stage and unresolved assumptions are obvious.
- Facts, evidence, hypotheses, and opinions remain distinguishable.
- Important decisions retain alternatives, counterarguments, approval, and provenance.
- Build/release transitions cannot silently bypass human gates.
- A promising idea can become an independent product repository without carrying the entire incubator.
- The user can resume work from repository artifacts rather than reconstructing intent from old chats.
