# Value Proposition

## Target customer

Developers, solo product builders, and small technical product teams using Cursor who can implement rapidly but want more discipline around discovery, evidence, irreversible decisions, and AI-agent coordination.

## Value proposition

Cursor Product OS turns the repository into a durable product-development operating layer: product state and gates show where the work is; specialist agents provide independent analysis; Skills encode repeatable methods; Hooks enforce runtime guardrails; Decision Council records disagreement and synthesis; optional Codex review adds an external second opinion when locally available; and promotion creates a clean one-product repository with provenance.

The core value is not more generated code. It is **better continuity and decision quality while preserving the speed of AI-assisted engineering**.

## Differentiation and alternatives

Unlike a generic documentation template, the OS connects product reasoning to executable validation and agent runtime controls. Unlike a chat-only workflow, it treats repository artifacts as the source of truth. Unlike a mandatory multi-model architecture, Codex is optional and fail-open. Unlike a hosted PM suite, v1 stays framework-agnostic and repository-native.

The strongest alternative is disciplined manual use of existing docs, issue trackers, ADRs, and code review. Cursor Product OS must prove through dogfooding that its integrated workflow saves more context and rework than the structure costs.
